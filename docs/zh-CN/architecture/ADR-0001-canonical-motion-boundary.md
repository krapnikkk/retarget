# ADR-0001：规范动作是唯一跨格式边界

> 本文是 [English](../../architecture/ADR-0001-canonical-motion-boundary.md) 的中文同步版。若中英文在法律、安全、治理或规范性要求上存在冲突，以英文版为准。

- 状态：已接受
- 日期：2026-08-13

## 背景

FBX、BVH、VMD、glTF、VRM 和 VRMA 对坐标轴、单位、静止姿势、骨骼名、插值和根运动的约定不同。若把加载器专用轨道直接交给预览或导出器，各目标端就会自行发明不同语义，甚至可能把动画绑定到导出器新建的骨架而非目标骨架。

## 决策

管线固定为 `Source -> Canonical -> Target`：

1. 有界证据探测选择源适配器；
2. 导入阶段把坐标、单位、别名、时间、插值和四元数连续性转换为 `RetargetedMotionClip`；
3. 求解阶段针对明确的目标静止骨架采样该片段；
4. 唯一的目标绑定器生成目标局部轨道，并以目标对象 UUID 寻址；
5. 预览和角色导出消费同一个绑定结果；
6. 独立动作导出只转换一次规范语义。

React 组件、预览场景或导出器都不得暗中重复源规范化。通用 FBX 仍是“静止姿势未知、单位未知”的配置；导入器可根据显式 `UnitScaleFactor` 缩窄单位，但不能因为扩展名是 `.fbx` 就继承 Mixamo 假设。

## 后果

新适配器必须暴露探测证据与配置身份。新的输出声明必须经过结构重载和独立语义比较。部分特殊骨架必须显式映射，不能乐观地自动转换。
