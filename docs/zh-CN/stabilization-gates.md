# 消费端安装前的稳定性门禁

> 本文是 [English](../stabilization-gates.md) 的中文同步版。若中英文在法律、安全、治理或规范性要求上存在冲突，以英文版为准。

不能仅因初次抽离能够构建，就让 `3dretarget-online` 安装 `3dretarget`。消费端集成必须另行批准，且需满足：

1. 公开入口名称及可序列化请求/结果契约完成 API 审查。
2. 打包后的浏览器入口能从安装归档解析 Worker，并通过真实 Vinext 生产启动冒烟测试。
3. 浏览器执行不再针对不受信任上传静默回退到 CPU 密集型内联工作。若为 Node 或测试保留内联执行，必须提供显式 API。
4. 按语义契约审查与 `3d-core` 的重叠，确保通用格式逻辑既不重复，也不通过提供商专用 API 耦合。
5. 已提交固定资源、可选下载语料、Golden Motion、结构重载、语义比较和生态回执均独立通过。
6. 包大小和浏览器分块影响具备基线测量；重型格式仍在应用主线程之外处理。
7. 在隔离 `3dretarget-online` worktree 中临时安装，且在不修改真实消费端的情况下通过类型检查、测试、Vinext 构建、生产启动冒烟和 Cloudflare 打包。
8. 切换 ADR 定义版本、回滚、源删除，以及两仓库暂存重复代码期间的修复处理方式。

只有通过这些门禁后，Web 仓库才应把本地引擎导入替换为包，并删除重复实现。
